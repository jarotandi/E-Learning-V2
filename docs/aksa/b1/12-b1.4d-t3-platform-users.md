## 2. Mission

Extract **two** domains out of the `AdminDashboard` monolith, with **zero behaviour change**:

1. **Platform / Overview** — the landing dashboard (`/admin`).
2. **Users & Roles** — the user directory (`/admin/users`).

Everything else (academic, studio, review, commerce, analytics, configuration) stays inside `AdminDashboard` for T4+. T3 does **not** start T4.

Scope was deliberately limited to these two domains because they are the least coupled to the remaining monolith and have the cleanest ownership story.

## 5. Single Users authority

| Concern | Owner |
|---|---|
| Users state (`users`) | `useAdminUsersDomain` (invoked by the persistent `AdminDashboard`) |
| Users persistence (`persistUsers`) | `useAdminUsersDomain` |
| Users view rendering | `AdminUsersPage` (view only; receives the domain surface as props) |

`AdminUsersPage` receives `{ domain, programs, rolePermissions, notify }` and **does not own** any users state. Users state is **not** placed in a route-mounted page, because Users data is consumed outside the Users tab.

### Cross-domain consumers (all share the ONE store)

All of the following read/write the **same** `users` / `persistUsers` pair from the single domain instance in `AdminDashboard`:

| Consumer | `AdminDashboard` line | Behaviour |
|---|---|---|
| Finance approval → Student creation | `persistUsers` at 717 | Unchanged |
| Lead → Student conversion | `persistUsers` at 821 | Unchanged |
| Contextual Add User (outside Users tab) | `persistUsers` at 880 | Unchanged |

There is **no second users store**, and `useAdminUsersDomain` does **not** import `AdminDashboard` (no cycle).

## 6. `adminStorage.ts` audit (KEEP)

`src/features/admin/adminStorage.ts` is a **26-line** module exporting a single pure reader:

```ts
export const readStorageArray = <T,>(key: string, fallback: T[] = []): T[] => { ... };
```

Purpose: `readStorageArray` used to be a **private helper inside `AdminDashboard.tsx`**. T3 extracts the Users domain, which needs the same reader, so the helper is lifted to one shared definition with **two callers** (the monolith and the users hook) instead of being duplicated.

It is acceptable and **kept** because it does **NOT**:

- create a second users store,
- own any localStorage state (it is a stateless read),
- duplicate persistence operations (all writes stay at their call sites),
- rename storage keys (keys remain inline literals at call sites),
- migrate other-domain storage,
- change read/write semantics (byte-identical body to the former private helper),
- become a broad repository/service abstraction (one function, 8 lines of body).

It contains **no key registry** — the 13 `theprams_demo_*` keys remain owned by the components that use them.
