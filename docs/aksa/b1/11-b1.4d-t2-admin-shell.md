## 2. Mission

Move **ADMIN APPLICATION CHROME** ownership out of the 6,498-line `AdminDashboard` monolith and into `AdminLayout`, the persistent `/admin/*` route element. `AdminDashboard` remains large temporarily — that is intentional. T3+ decomposes business domains.

```text
BEFORE                                   AFTER T2
AdminLayout                              AdminLayout
 └─ Outlet                                └─ AdminShellProvider
     └─ LegacyRouteBridge                      └─ AKSA Admin Shell
         └─ AdminDashboard                         ├─ desktop sidebar
             ├─ sidebar                            ├─ mobile navigation
             ├─ branding                           ├─ role switcher
             ├─ role switcher                      ├─ identity / logout
             ├─ identity / logout                  ├─ shell top bar
             ├─ top header                         └─ Outlet
             └─ business content                       └─ LegacyRouteBridge
                                                           └─ AdminDashboard
                                                               └─ BUSINESS CONTENT ONLY
```

`AdminLayout` is mounted as the `/admin/*` route element inside `LegacyAppStateProvider` (`AppRouter.tsx`), so it stays mounted across all canonical admin child navigation. Shell-level state placed there therefore survives tab changes.

## 4. AdminShellContext Contract

`src/features/admin/shell/AdminShellContext.tsx` exports `AdminShellProvider` and `useAdminShell()`.

### Owned state (and only this)

| Member | Type | Notes |
|---|---|---|
| `adminRole` | `AdminRole` | UI presentation role. Default `'Super Admin'`. |
| `setAdminRole` | `(role) => void` | Updates role, then navigates to `/admin` (overview). |
| `activeTab` | `AdminTab` | Derived from URL: `adminPathToTab(location.pathname) ?? 'overview'`. |
| `navigateToTab` | `(tab) => void` | `navigate(adminTabToPath(tab))`. |
| `isTabAllowed` | `(tab) => boolean` | `isAdminTabAllowed(adminRole, tab)` (UI filtering). |
| `allowedTabs` | `AdminTab[]` | `ADMIN_ROLE_PERMISSIONS[adminRole]` copy. |
| `logout` | `() => void` | Adapter to `LegacyAppStateProvider.requestLogout`. |

### Deliberately NOT owned

Business-domain state — users, leads, finance, programs, questions, blog posts, video lessons, forms, filters, modals, toasts, audit records, notifications, `searchTerm`, `actionMessage` — stays in `AdminDashboard` until its owning domain is extracted in T3+. Lifting those 70+ slices here would move the monolith rather than decompose it.

### Provider location

`AdminShellProvider` is mounted **inside `AdminLayout`**, never inside `AdminDashboard`, and is **not keyed by pathname**. `AdminLayout` obtains `requestLogout` from `useLegacyAppState()` and passes it as `onLogout`, so logout keeps the existing confirmation flow. `AdminLayout` never calls `setUser(null)` directly.

Navigation metadata (`ADMIN_NAV_ITEMS`, labels, Lucide icons, exact legacy order) lives in `src/features/admin/shell/adminNavigation.ts`, kept separate from the pure routing model.

## 5. Role Semantics (UI presentation only)

The role matrix is unchanged and imported from the pure model (`ADMIN_ROLE_PERMISSIONS` / `isAdminTabAllowed`):

| Role | Allowed tabs (count) |
|---|---|
| **Super Admin** | all 13 |
| **Content Manager** | overview, programs, content, questions, testimonials, website (6) |
| **Support** | overview, users, leads, inquiries, settings, finance (6) |

- Role switch → `setAdminRole` updates `adminRole` then navigates to `/admin` (overview). Legacy reset-to-overview semantics preserved.
- Debug role switcher remains visible **only** while `adminRole === 'Super Admin'` (legacy behavioural contract preserved). It is a debug affordance, not production RBAC.
- Identity semantics preserved: Super Admin shows "dr. Pramono"; other roles show the role label. Zero authentication state is created.

### Disallowed direct URL — UI presentation redirect

T1 introduced direct tab URLs. T2 preserves the old UI role-filter behaviour: if a non-Super-Admin role lands on a tab URL it cannot see (e.g. Content Manager at `/admin/commerce/finance`), `AdminShellContext` corrects presentation with `navigate(adminTabToPath('overview'), { replace: true })`.

Label: **UI presentation redirect** — **not** access control / security. No 403, no auth claim, no `Guarded`, no auth provider, no Supabase.

## 6. Mobile Navigation

The legacy admin sidebar was desktop-only (`hidden lg:flex`) with no mobile equivalent. T2 establishes mobile access in `AdminLayout`:

- Menu button visible below `lg` (≥44×44, `aria-label="Buka menu admin"`, `aria-expanded`, `aria-controls`).
- Drawer contains the same role-filtered nav items, active item exposed (`aria-current="page"`), nav items ≥48px.
- Selecting a nav item navigates and closes the drawer (route-change effect).
- Escape closes the drawer; focus returns to the menu button.
- Backdrop click closes the drawer.
- Body scroll is locked while open and restored on close.
- Drawer close button ≥44×44 (`aria-label="Tutup menu admin"`).

Accessibility is **source-contract + smoke** only. A formal visual/WCAG acceptance remains B1.5/T10.

### Desktop sidebar

At `lg+`, exactly one sidebar (`w-64`, AKSA styling, role-filtered navigation). There is no second sidebar inside `AdminDashboard`.

### Shell top bar

`AdminLayout` owns a single shell top bar (AKSA eyebrow + current section title). Below `lg` it also carries the mobile menu button. It is structural chrome, not a business header.

## 7. Search + Bell — Transitional Decision

The legacy application header carried two business-coupled controls:

1. **Search input** — bound to `searchTerm`, which filters users.
2. **Bell button** — invokes `notify(...)`, which uses `actionMessage`.

These were **not** lifted into `AdminShellContext` and **not** deleted. Instead:

- `AdminLayout` gets a new structural shell top bar (menu button + section title).
- The Search + Bell controls are **re-homed as a non-sticky content toolbar** inside `AdminDashboard`, still bound to `searchTerm` / `setSearchTerm` / `notify`.
- The toolbar has `aria-label="Cari dashboard"` (search) and `aria-label="Lihat notifikasi admin"` (bell), bell ≥44×44.
- `actionMessage` and `notify()` stay business-owned in `AdminDashboard` (many business actions depend on `notify()`).

This is intentional transitional architecture. T3 will place user-domain search with Users; notification ownership is assigned later.
