## 5. Website / Blog state ownership (single authority)

- Canonical Website/Blog owner: `useAdminWebsiteDomain({ blogPosts, onBlogPostsChange, notify, recordAudit })`, invoked **once** by the **persistent** `AdminDashboard`.
- `AdminWebsiteEditorPage` is **view only** and receives `{ domain, onPreviewWebsite }`; the five dialogs receive `domain`.
- The page and dialogs declare **no local `useState`** and do **not** invoke the hook.
- The extracted page/dialogs never import `AdminDashboard` or `LegacyAppStateProvider` (no cycle).

### Why a hook, not a route-mounted page

The legacy `AdminDashboard` kept the Website/Blog state **above** the conditional `activeTab === 'website'` JSX, so an in-progress article draft / asset edit / modal flag survived client-side tab changes. Moving the state into a page that only mounts for `/admin/studio/website` would silently lose that behaviour. The hook is therefore invoked by the persistent orchestrator, preserving parity (proved in the browser — see §15).

The five dialogs are rendered as **siblings of the tab conditionals** (exactly where the legacy `AnimatePresence` blocks sat), not inside the `activeTab === 'website'` branch — so an open editor persists across a client-side tab change exactly as before.

### Dependency order

`notify` → `recordAudit` → `programsList` → `useAdminUsersDomain` → `useAdminQuestionsDomain` → `useAdminContentDomain` → **`useAdminWebsiteDomain`** → consumers. All injected dependencies are initialised before the hook call — **no TDZ/runtime-order hazard**.

### `setView` stays outside the domain

`setView` is **not** part of the domain. The legacy "Preview Changes" navigation is preserved by passing a narrow callback: `<AdminWebsiteEditorPage domain={websiteDomain} onPreviewWebsite={() => setView?.('landing')} />`. No routing moved into the domain.
