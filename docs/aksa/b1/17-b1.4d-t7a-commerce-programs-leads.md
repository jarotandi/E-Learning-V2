## 2. Mission

Extract **only** the two Commerce surfaces out of the `AdminDashboard` monolith with **zero behaviour change**:

- `/admin/commerce/programs` — **Program Inventory & Curriculum** (search/filter, metric cards, table, full editor modal, save-confirm dialog, contextual New Program draft, Reset).
- `/admin/commerce/leads` — **Lead Management** (table with persisted + in-memory leads, Add New Lead modal, Detail Lead modal with status pipeline + WhatsApp + Convert to Student, contextual Add Demo Lead).

**Two focused domain hooks, not one giant Commerce store:**

```
AdminDashboard
  ├─ useAdminProgramsDomain({ programs, onProgramsChange, notify, recordAudit })  -> <AdminProgramsPage />
  ├─ useAdminLeadsDomain({ programs, users, persistUsers, notify, recordAudit })   -> <AdminLeadsPage />
  └─ remaining legacy domains
```

**Marketing (`/admin/commerce/marketing`) and Finance (`/admin/commerce/finance`) are NOT extracted — they stay in AdminDashboard (T7B / T8).**

## 5. Programs — single authority + prop bridge

`useAdminProgramsDomain({ programs, onProgramsChange, notify, recordAudit })` is invoked **exactly once** by the persistent `AdminDashboard`. The hook owns `programsList`, `editingProgram`, `programPendingSave`, `programSearchTerm`, `programCategoryFilter` and all Programs operations/derived values. The route-mounted `AdminProgramsPage` does **not** invoke the hook.

- **Legacy prop bridge preserved (no persistence):**
  ```ts
  const [programsList, setProgramsList] = useState<Program[]>(programs);
  useEffect(() => setProgramsList(programs), [programs]);
  ```
- `onProgramsChange` is invoked on save, delete, reset — so any parent consumer receives the updated list.
- **Canonical editable list:** `programsDomain.programsList` is the **single** `Program[]` that feeds:
  - Users domain (`programs: programsDomain.programsList`)
  - Content Library editor (`programs={programsDomain.programsList}`)
  - Leads domain (`programs: programsDomain.programsList`)
  - Programs page itself
- There is **deliberately NO second `programsList` store**.

## 7. Leads — in-memory + persisted dual source + conversion

`useAdminLeadsDomain({ programs, users, persistUsers, notify, recordAudit })` is invoked **exactly once** by the persistent `AdminDashboard`. The hook owns `leadsList`, `selectedLead`, `leadPendingConvert`, `isLeadFormOpen`, `leadForm`, `leadNoteDraft` and all Lead operations.

- **Dual data source preserved exactly:**
  - `localLeads` = `JSON.parse(localStorage.getItem('theprams_demo_leads') || '[]')` (catch `[]`) — recomputed every render.
  - `leadsList` = in-memory leads (seeded from `MOCK_LEADS` + demo adds).
  - `allLeads` = `[...localLeads, ...leadsList]` (local persisted leads first).
- **Canonical key (exact, unchanged):** `theprams_demo_leads`, declared once as `LEAD_STORAGE_KEY` in `adminLeadsData.ts`.
- **Cross-domain dependencies (injected, never imported):**
  - `programs` / `users` / `persistUsers` from the canonical Programs and Users domains.
  - Lead → Student conversion persists through `usersDomain.persistUsers` — **NO second Users store** and **NO second UserAccount persistence implementation**.
- **Notify re-exposed** on the domain result so the Detail dialog can keep its legacy toasts.
