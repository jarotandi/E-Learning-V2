## 5. Question state ownership (single authority)

| Concern | Owner |
|---|---|
| `questions` | `useAdminQuestionsDomain` (invoked by the persistent `AdminDashboard`) |
| `editingQuestion` | `useAdminQuestionsDomain` |
| `availableTags` | `useAdminQuestionsDomain` |
| `isImportModalOpen` / `importStatus` | `useAdminQuestionsDomain` |
| `isManageTagsModalOpen` / `newTagInput` | `useAdminQuestionsDomain` |
| Question view rendering | `AdminQuestionBankPage` (view only; receives `{ domain, onDownloadTemplate }`) |

`AdminQuestionBankPage` and the dialogs **own no question state**. The page receives the canonical domain surface as props.

### Why a hook, not a route-mounted page

The legacy `AdminDashboard` kept the Question Bank state **above** the conditional `activeTab === 'questions'` JSX, so a transient draft survived tab changes. Moving that state into a page that only mounts for `/admin/academic/questions` would silently lose the behaviour. The hook is therefore invoked **once** by the **persistent** `AdminDashboard`, exactly like the T3 Users domain hook.

The hook injects **only** `notify` (the toast adapter, still business-owned by `AdminDashboard`). It does **not** import `AdminDashboard` (no cycle), and it does not take finance / users / programs / Studio state.

## 6. The TWO question-create paths (preserved, not normalised)

The source really had **two different** "new question" drafts, and T4 keeps both as explicit operations:

| Path | Trigger | Options | Operation |
|---|---|---|---|
| Primary | "Add Question" button | **five** options `A–E` | `openNewQuestion()` |
| Legacy contextual | `runContextualAdd()` (shared contextual Add) | **two** options `A–B` | `openContextualQuestionDraft()` |

Both seed `subject: 'Penalaran Umum'`, `difficulty: 'Medium'`, `text: ''`, `correctOptionId: 'A'`, `explanation: ''`, `program: 'SNBT'`, `tags: []`, and a `Date.now()` id — they differ **only** in the option count. This difference is preserved; §13's verifier asserts the two drafts stay different at runtime.

`runContextualAdd`'s question branch now calls the canonical operation:

```ts
} else if (activeTab === 'questions') {
  questionsDomain.openContextualQuestionDraft();
}
```

All other `runContextualAdd` branches (leads, users, programs, content, …) are untouched.

## 8. CSV batch import (demo simulation, unchanged)

The import is a **demo simulation** — the source has **no CSV parser**, and T4 does **not** add one:

- a file selection only proves "file presence" (`if (!file) return;`);
- selecting a file moves `idle → processing` (2000 ms), prepends **two fixed demo questions**, then `done`;
- the modal closes 1500 ms later and the status resets to `idle`.

T4 preserves this exactly and adds **no parser dependency**. The import dialog holds **no** video/upload state.

### CSV template download

The template button calls the existing shared business helper `downloadTextFile(...)` through the narrow `onDownloadTemplate` callback passed down from `AdminDashboard`. The generic download helper was **not** moved into the academic domain, and the filename / CSV content are unchanged.

## 11. Accessibility (extracted Academic surface only)

- **Row actions** (`Duplicate` / `Edit` / `Delete`) carry `aria-label` (`Duplikasi soal …`, `Edit soal …`, `Hapus soal …`) and **44×44** targets via the design-system `IconButton`.
- The row-action container gained **`focus-within:opacity-100`**, so keyboard focus reveals the actions (no hover-only access).
- **All three dialog close buttons** (editor / categories / import) have `aria-label` and a **44px** min target.
- **Correct-answer controls** are **44×44** (`w-11 h-11`) and expose `aria-pressed`.
- The **selected correct option** and **selected tags** use an accessible dark emerald (`emerald-700`) instead of white text on the raw brand teal (`bg-brand-blue`); `0` inaccessible selected-tag controls remain.
- Tag delete controls carry `aria-label={`Hapus tag ${tag}`}`.
- **Contrast:** within the extracted Academic surface only, `text-brand-blue` / `text-brand-orange` / `emerald-600` normal/small text was migrated to accessible alternatives (`emerald-700`, `amber-700`, `red-700`, `slate-…`). Decorative icon colours (e.g. header icons) were **preserved**; untouched legacy domains were **not** rewritten.
- **Buttons:** the extracted Academic actions prefer the B1.4A design-system `Button` / `IconButton`; design-system internals were **not** modified and the migration was **not** broadened.
