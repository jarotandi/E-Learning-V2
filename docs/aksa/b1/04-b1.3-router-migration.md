### Shells

| Shell | What it owns |
|---|---|
| `LearnerLayout` | 64px desktop / 56px mobile header, 256px sidebar, drawer, 5-item mobile bottom bar |
| `StudioLayout` | Studio shell + 10 route boundaries, all placeholders |
| `PublicLayout` | Route boundary; hosts the **legacy `Navbar`** as the single public chrome owner |
| `AdminLayout` | Structural host only — `<Outlet/>`, no chrome |

**The double-chrome rule.** A surface is wrapped in a layout only when the legacy
component it renders carries no navigation chrome of its own. `StudentDashboard`
and `LearningPage` do carry their own, so they render **bare**, exactly as before
the router existed. Decomposing them is B1.4 work. `AdminLayout` returns only an
`<Outlet/>` because `AdminDashboard` already renders its own 256px `<aside>` and
its own header; adding shell chrome would double both.

`PublicLayout` deliberately hosts the existing legacy `Navbar` rather than a new
AKSA public header. Re-implementing it would produce two public headers, and
replacing the "Bimbel The Prams" wordmark is explicitly out of B1.3 scope.

## Defects found during B1.3 and fixed in place

Three real defects were found by the runtime smoke. All three are in files B1.3
owns, and all three are fixed in the implementation commit with the measured
evidence recorded at the fix site in the source.

### DEFECT-1 — `AnimatePresence mode="wait"` silently swallowed router navigation

**Severity: critical.** This defeated the entire purpose of the sub-batch.

Symptom: the URL updated but the rendered page never changed.

| Action | URL after | Rendered after |
|---|---|---|
| Click program card on `/programs` | `/programs/snbt-kedokteran` | **program listing**, still mounted >10s later |
| Click Navbar "E-Learning Program" on `/` | `/programs` | **landing page**, still mounted |

Cause: consecutive legacy routes live in the same layout branch, so React
reconciles `LegacyRouteBridge` in place. The `motion.div` key changes,
`AnimatePresence mode="wait"` keeps the **exiting** child mounted until its exit
animation reports completion — and that completion never arrives, with these
children being `React.lazy` under `Suspense` and `StrictMode` on React 19.2.5 and
motion 12.38.0. The exiting child therefore stayed mounted at its `animate`
values forever, permanently shadowing the new route. Sampling the element's
`opacity` / `transform` at 0/1/3/6s showed `1 | none` throughout: the exit never
even started.

Cross-branch navigation (`/programs` → `/admin`) still worked, because there
React replaces the whole subtree and `initial={false}` renders instantly. That is
why this was easy to miss, and why a shallow test would have passed.

Fix: drop the presence protocol and keep the **enter** animation only. React
unmounts the old child and mounts the new one directly on the key change, so
navigation can no longer be swallowed, and the 0.3s fade/slide-in the user
actually sees is preserved. Only the fade-**out** is dropped. Correctness of
navigation outranks a cosmetic exit transition.

Re-verified after the fix: program listing → detail, Navbar navigation,
exam → result, and browser back/forward all change both URL and view.

**Follow-up (B1.4):** restoring the exit animation requires the presence
mechanism to be reliable under `React.lazy` + `Suspense` + `StrictMode`. It must
not be reintroduced without a browser test that asserts the view actually changes.

### DEFECT-2 — learner header pinned to 56px at every width

**Severity: medium.** Visible layout overflow on desktop.

`<header>` carried an inline `style={{ height: '3.5rem' }}` while an injected
`<style>` rule resized only an **inner** `<div>` to `layout.nav.headerHeight`
(4rem). Inline styles beat stylesheet rules, so the measured header stayed 56px
at every viewport while its content became 64px from 768px up.

Measured at a 1000px viewport before the fix: outer header 56px, inner content
64px, 8px of overflow.

Fix: the responsive height now lives on the element that is actually measured —
`className="sticky top-0 z-40 h-14 md:h-16 …"`. `h-14` is 3.5rem and `h-16` is
4rem, which is exactly `layout.nav.headerHeight`, so the token and the CSS agree
and the injected `<style>` element is gone. The drawer's header row was aligned
the same way.

Measured after the fix: header 64px, `scrollHeight` 63px, no overflow.

### DEFECT-3 — no navigation at all between 768px and 1023px

**Severity: medium.** The whole band was unnavigable.

The drawer trigger was `md:hidden` (768px) while the sidebar is `lg:flex`
(1024px) and the bottom bar is also `md:hidden`. Between those two breakpoints
all three were hidden simultaneously.

Measured at 1000px before the fix: hamburger `display:none`, sidebar
`display:none`, bottom bar `display:none`.

`docs/aksa/design/03-learner-shell.md` requires:

| Breakpoint | Sidebar | Header |
|---|---|---|
| 1024px+ (lg) | Full 256px sidebar | Full 64px |
| 768–1023px (md) | Collapsible drawer | Full 64px |
| <768px | Hidden (drawer) | Compact 56px |

Fix: the trigger is now `lg:hidden`, matching the sidebar. The implementation is
brought into line with the approved contract; the contract was not rewritten.

Measured after the fix at 1000px: hamburger `display:block`, header 64px, sidebar
`hidden`, bottom bar `hidden` — exactly the md row of the table.

## Deviations from the B0 draft route map

Recorded here rather than silently absorbed. `04-route-map.md` was amended in the
same documentation commit.

- **CONF-02 closed.** `/app/library`, `/app/partner-practice`, `/app/community`,
  `/app/rewards` and `/app/help` were required by B1.3's route table. All five are
  registered as planned routes, and the route map now lists them.
- **`/blog/:blogId`, not `/blog/:slug`.** The B0 draft wrote the parameter as
  `:slug`. The legacy data is keyed by id (`BLOG_POSTS[].id`) and has no slug
  field, so the param is `:blogId`. Naming only; no behaviour change.
- **`/app/learn/:lessonId` is not a route.** Lesson selection is in-page state
  inside the learning workspace, not a routable capability.
- **Admin sub-routes are not registered.** The twelve `/admin/*` targets need the
  `AdminDashboard` decomposition first. They resolve to the explicit 404 rather
  than silently falling back to the landing view.
- **`/educator/*` is not registered.** It depends on a real educator identity and
  capability model, which is B2.
- **`/studio/editor` (no id) was added** beyond the B0 draft, resolving to the
  same editor placeholder.

## B1.4 follow-ups

Carried forward, in the order they will bite:

1. **Do not reintroduce `AnimatePresence` without a browser test** (DEFECT-1).
2. **Decompose `AdminDashboard`** (408.8 KB, 418,614 bytes) into the eight target
   sections, then register the `/admin/*` sub-routes.
3. **Decompose `StudentDashboard` and `LearningPage`** so they stop carrying their
   own chrome and can move into `LearnerLayout`. This is what makes the learner
   shell universal.

   replacement (`The Prams` → AKSA) per domain.
5. **Build the design-system primitives** (`Button`, `Card`, `Badge`, `Input`,
   `Tabs`, `Table`) and migrate to tokens. `src/index.css` stays authoritative
   until then.
6. **Re-verify the responsive breakpoints visually** — the learner sidebar at
   ≥1024px and the bottom bar at <768px were verified structurally only (see
   NOT VERIFIED above).
7. **Enforce `requiredCapabilities` in navigation.** The mechanism lands in B1.4;
   real enforcement needs B2 identity, so navigation currently marks capability
   with a status field rather than filtering it.
8. **Decompose `LandingPage` and the program pages** into `features/public/*`.
