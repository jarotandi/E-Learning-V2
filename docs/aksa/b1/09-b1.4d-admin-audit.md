## 10. Legacy Bridge Strategy Recommendation

**Recommended: Option A — Compatibility Bridge for all admin child URLs**

- `pathToLegacyView('/admin/*')` → `'admin'`
- Keep one compatibility bridge for all admin child URLs
- `LegacyRouteBridge` renders `AdminDashboard` for all `/admin/*` paths
- `currentView === 'admin'` remains the gate

**Rationale:**
- Preserves all transient state (form drafts, editing records, etc.)
- Minimal complexity — no new bridge infrastructure
- No impact on `LegacyAppStateProvider` semantics
- Deep links work (all `/admin/*` routes resolve to admin view)
- Back/forward navigation works

**Alternative (Option B):** New admin route bridge bypassing legacy view switch — higher complexity, higher risk, not recommended for B1.4D.

## 11. State Preservation Risk Analysis

### Current behaviour: Tab switches via `setActiveTab(...)` within ONE mounted AdminDashboard
- Transient state survives tab switches
- No remount, no state loss

### B1.4D with child routes:
- **Risk:** Ordinary child-route navigation may REMOUNT section state
- **Impact:** Form drafts, editing records, selected items, filters could reset

### Mitigation:
- Use a single `AdminWorkspacePage` that owns all domain state
- Child routes render section components that receive state via props/context
- OR: Keep `AdminWorkspacePage` as the single state owner, with section components as views within it (not separate routes)
- Preserve the existing `setActiveTab` semantics where possible

### Critical transient states at risk:
- Form drafts (campaign, finance, lead, user, program, blog, question, video)
- Editing records (selectedLead, selectedFinanceRecord, editingUser, etc.)
- Filters/search terms
- Modal open states
- Upload progress
- Preview state
